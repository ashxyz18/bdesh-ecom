## Remaining Issue: Admin Authentication

### Problem
There is **no separate admin login system**. The same `/api/auth/login` endpoint is used for both regular users and admins. To access `/admin/templates` and upload website templates, the admin must currently sign up as a regular user at `/signup`, then manually navigate to `/admin/templates`.

### Missing Features
1. **No role-based access control**: The `User` interface in `data-store.ts` has no `role` or `isAdmin` field.
2. **No admin login page**: There is no `/admin/login` or dedicated admin authentication flow.
3. **No admin middleware**: The `/admin/*` routes and `/api/admin/*` API routes have no guard to prevent non-admin access.
4. **Hardcoded admin credentials**: There is no seeded default admin account for first-time setup.

### Goal 4: Admin Login & Access Control
- [x] **Add `role` to `User`**: Update the `User` interface in `lib/data-store.ts` to include `role: "user" | "admin"`.
- [x] **Seed default admin**: In `app/layout.tsx` or a data store init module, create a default admin account (e.g., `admin@bdesh.shop` / `admin123`).
- [x] **Fix `/api/admin/templates`**: Update the upload API to check for the `x-admin-key` header or validate the `role` from a proper session.
- [x] **Protect routes**: Add middleware or checks to `/admin/*` and `/api/admin/*` to ensure only admins can access them.
- [x] **UI updates**: Show/hide admin links (e.g., "Admin Dashboard" in sidebar) based on the user's role.
- [x] **User registration update**: When a new user signs up, default their role to `"user"`.

### How to Log In (Current State)
The user can currently log in via `/login` using any credentials that were used during `/signup` (stored in-memory). To become an admin, the system needs to be modified to distinguish roles.

## Backend Database TypeScript Fix (seed.ts)

### Problem
Line 100 in `backend/database/src/seed.ts` throws the error:
```
ts Cannot find name 'process'. Do you need to install type definitions for node? Try npm i --save-dev @types/node and then add 'node' to the types field in your tsconfig. (2591)
```

### Root Cause
The `tsconfig.json` in `backend/database/` does not include `@types/node` in its compilation scope. The file uses `process.exit(1)` at the bottom of the seed script. Since `process` is a Node.js global, TypeScript needs the Node.js type definitions to recognize it.

### Fix
1. Add `@types/node` to the `backend/database` workspace.
2. Update `backend/database/tsconfig.json` to include `"types": ["node"]` in `compilerOptions`.

### Potential Other Issues
1. The seed script uses `prisma` directly without a surrounding try-catch in the `main()` function itself (only in the `.catch()` block). If `prisma` throws synchronously, the error won't be caught.
2. The `password` is hardcoded and plaintext (though it's a bcrypt hash, it's still better to generate it dynamically for security).
