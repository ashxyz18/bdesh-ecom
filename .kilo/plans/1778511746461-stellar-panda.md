# Plan: Render All Uploaded Templates as React Components with Full Interactivity

## Goal
Replace the iframe-based rendering for uploaded templates with a React component approach that provides full interactivity (cart, search, mobile menu, toast, etc.), just like the hardcoded `KoskiiTemplate`.

## Current State
- `koskii` template: Hardcoded React component (`KoskiiTemplate`) with full interactivity (cart, toast, search, mobile menu, hero slider, product cards, wishlist, etc.)
- All other uploaded templates: Rendered via `IframeTemplateStore` in `frontend/web/app/store/[storeId]/page.tsx` — no React interactivity, just a static iframe.

---

## Approach

Create a `DynamicTemplate` React component that:
1. Fetches the uploaded template's HTML content from the API
2. Parses the HTML to build a React-renderable structure
3. Maps store data (name, logo, products, settings) into the template's sections dynamically
4. Injects full React interactivity (cart, toast, search, mobile menu, etc.) via shared contexts and event handlers
5. Loads the template's CSS files into the page

This is similar to how `KoskiiTemplate` works, but generic enough to work with any uploaded template.

---

## Files to Create

### 1. `frontend/web/lib/templates/dynamic/DynamicTemplate.tsx`
A generic React template wrapper component that:
- Accepts `store` and `products` props (same as `KoskiiTemplate`)
- Accepts a `templateId` prop to identify which uploaded template to load
- Fetches the template's HTML from `/api/templates/{templateId}`
- Renders the template's HTML structure with `dangerouslySetInnerHTML`
- Uses React refs and effects to inject interactivity after render:
  - Cart functionality (add to cart, quick add)
  - Search overlay
  - Mobile menu
  - Wishlist toggle
  - Hero slider auto-rotation
  - Scroll effects
  - Product card interactions
- Loads template CSS dynamically by injecting `<link>` tags into `<head>`
- Maps template sections based on the manifest's `sections` configuration
- Uses `CartContext` and `ToastContext` for shared state (same as `KoskiiTemplate`)

### 2. `frontend/web/app/api/templates/[templateId]/route.ts`
A new API route that serves a specific template's manifest and file content (HTML, CSS, JS) so the `DynamicTemplate` component can fetch and render it.

---

## Files to Modify

### 3. `frontend/web/app/store/[storeId]/page.tsx`
Remove the `IframeTemplateStore` component and update `StorePage` to:
- Always use the React component path (remove the `templateId === "koskii"` special case)
- Render `KoskiiTemplate` when `templateId === "koskii"`
- Render `DynamicTemplate` for all other templates
- Pass `store` and `products` to `DynamicTemplate`

## Implementation Steps

### Phase 1: Create the API Route
- Create `frontend/web/app/api/templates/[templateId]/route.ts`:
  - `GET`: Reads the template from the registry by `templateId`
  - Returns the template's HTML content, CSS file list, JS file list, and manifest

### Phase 2: Create DynamicTemplate Component
- Create `frontend/web/lib/templates/dynamic/DynamicTemplate.tsx`:
  - Fetch template data from the new API route
  - Inject CSS into `<head>` via `<link>` tags
  - Render HTML content using `dangerouslySetInnerHTML` on a container ref
  - After rendering, use `useEffect` to query the DOM and attach React-powered interactivity:
    - Find elements matching manifest selectors for sections (logo, hero, products, cart, search, mobile menu, wishlist, newsletter)
    - Replace product placeholders with actual product data
    - Add click event listeners for cart, search, mobile menu, wishlist, newsletter
    - Attach scroll handlers for header styling
    - Implement hero slider auto-rotation if a hero section exists
  - All interactivity should use the existing `useCart()` and `useToast()` hooks, just like `KoskiiTemplate`
  - Implement a loading skeleton while fetching the template
  - Implement error state if template fetch fails

### Phase 3: Update Store Page
- Modify `frontend/web/app/store/[storeId]/page.tsx`:
  - Import `DynamicTemplate`
  - Remove `IframeTemplateStore`
  - In the render logic:
    - If `templateId === "koskii"`, render `KoskiiTemplate`
    - Otherwise, render `DynamicTemplate` with `templateId`, `store`, and `products`
  - Keep `CartProvider` and `ToastProvider` wrapping both paths

### Phase 4: Add Type Definitions
- Update `frontend/web/lib/templates/types.ts` if needed to support dynamic template props

### Phase 5: Testing
- Verify koskii template still works as before
- Upload a test template and verify it renders as a React component
- Verify cart, search, mobile menu, and toast work on uploaded templates
- Verify products are injected into the template's product grid
- Verify CSS is loaded correctly

## Concerns & Mitigation
- **Cross-browser DOM manipulation**: Use React refs and effects carefully; avoid direct DOM mutation where possible
- **CSS isolation**: Templates may have conflicting CSS. Consider prefixing or scoping CSS. For now, rely on template authors to use BEM or scoped styles
- **JS conflicts**: Uploaded templates may have inline scripts. `DynamicTemplate` should strip inline scripts and replace with React interactivity
- **Performance**: Fetching and parsing HTML at runtime has overhead. Cache template data and consider SSR for pre-built templates
