# Plan: Deploy to Railway WITHOUT Dockerfile (Use Nixpacks Only)

## Problem
Railway deployment is stuck/very slow because:
1. Dockerfile builds are heavy and error-prone with monorepo + Next.js 16.2.4
2. Turbopack (enabled by default in Next.js 16.x) breaks workspace resolution
3. Multi-stage Docker builds break npm workspace symlinks

## Solution: Use Nixpacks (No Dockerfile)

### Step 1: Remove ALL Dockerfiles
Railway auto-detects `Dockerfile` and ignores `railway.toml` builder setting. Must remove/backup all Dockerfiles.

```bash
# Backup and remove Dockerfile
git mv Dockerfile Dockerfile.bak
# If Dockerfile.bak exists, just delete it
git rm -f Dockerfile.bak
```

### Step 2: Update railway.toml for Nixpacks
Nixpacks handles monorepos better than Docker. Configure it properly:

```toml
[build]
builder = "nixpacks"
buildCommand = "cd apps/web && NEXT_TURBOPACK=0 npm run build"
startCommand = "cd apps/web && npx next start -p $PORT"

[deploy]
healthcheckPath = "/"
healthcheckTimeout = 300
restartPolicyType = "on_failure"
restartPolicyMaxRetries = 3
```

### Step 3: Fix Root Directory in Railway Dashboard
Nixpacks needs to know where the Next.js app is. You MUST set this in Railway dashboard:

1. Go to: https://railway.com/project/d152781b-aca5-49bc-a153-4a6012e34978
2. Click on **web** service
3. Go to **Settings** tab
4. Set **Root Directory** to `apps/web`
5. Click **Save**

### Step 4: Fix package.json for Nixpacks
Ensure `apps/web/package.json` has correct build script:

```json
"scripts": {
  "build": "NEXT_TURBOPACK=0 next build",
  "start": "next start"
}
```

Also remove `packageManager` field from root `package.json` to avoid yarn errors:
```json
// Remove this line:
"packageManager": "npm@11.8.0",
```

### Step 5: Commit & Push
```bash
git add -A
git commit -m "fix: remove Dockerfile, use Nixpacks, disable Turbopack"
git push origin master
```

### Step 6: Trigger Railway Deployment
```bash
# Link to web service
railway link -p sincere-optimism -s web

# Deploy (Nixpacks will auto-detect)
railway up --detach
```

### Step 7: Set Environment Variables in Railway Dashboard
After deployment starts, go to Railway dashboard:

1. **Add PostgreSQL** if not added: Click "+ New Service" → "Database" → "PostgreSQL"
2. **Set Environment Variables** in web service:
   - `DATABASE_URL` → Click "Reference" → Select PostgreSQL → `DATABASE_URL`
   - `NEXT_PUBLIC_APP_URL` = `https://sincere-optimism.up.railway.app`
   - `NEXT_PUBLIC_BASE_URL` = `https://sincere-optimism.up.railway.app`
   - `OPENAI_API_KEY` = your API key

## Why This Works
- **No Dockerfile** = Railway uses Nixpacks (faster, handles monorepos)
- **Root Directory = apps/web** = Nixpacks knows where Next.js is
- **NEXT_TURBOPACK=0** = Disables Turbopack (fixes workspace errors)
- **No packageManager field** = Nixpacks won't try to use yarn

## Expected Build Time
- Nixpacks: ~2-3 minutes (vs Docker ~5-10 minutes)
- First deploy might take longer (installing dependencies)
