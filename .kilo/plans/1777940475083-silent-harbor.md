# Plan: Fix Railway Deployment - Avoid Turbopack Completely

## Problem Analysis

Railway build fails because:
1. Turbopack (enabled by default in Next.js 16.2.4) tries to load `autoprefixer` 
2. Setting `NEXT_TURBOPACK=0` doesn't work when passed via `npm run build`
3. The `apps/web/.next/build` directory has cached Turbopack build artifacts

## Solution: Build Without Turbopack in Dockerfile

### Step 1: Update Dockerfile to Delete Turbopack Cache

Add these lines BEFORE the build command:

```dockerfile
# Clean any cached Turbopack artifacts
RUN rm -rf apps/web/.next && rm -rf apps/web/node_modules/.cache

# Build with Turbopack completely disabled  
RUN cd apps/web && NEXT_TURBOPACK=0 npx next build
```

### Step 2: Ensure postcss.config.mjs Doesn't Reference autoprefixer

Already done - we removed `autoprefixer` from `postcss.config.mjs`.

### Step 3: Commit and Push

```bash
git add Dockerfile
git commit -m "fix: clean Turbopack cache before build"
git push origin master
```

### Step 4: Deploy to Railway

```bash
railway redeploy --yes
```
