# Plan: Deploy to Railway ASAP (Simplified)

## Problem
Railway deployment failing due to Dockerfile build errors with Next.js 16.2.4 + Turbopack + monorepo workspace issues.

## Fastest Solution (3 Steps)

### Step 1: Remove Dockerfile (Force Nixpacks)
Railway uses Dockerfile when present, even if `railway.toml` specifies Nixpacks. Removing it forces Railway to use Nixpacks which handles monorepos better.

```bash
# Rename Dockerfile so Railway ignores it
git mv Dockerfile Dockerfile.bak
```

### Step 2: Update railway.toml for Nixpacks
```toml
[build]
builder = "nixpacks"
buildCommand = "npx turbo run build --filter=@bdesh/web"
startCommand = "cd apps/web && npx next start -p $PORT"

[deploy]
healthcheckPath = "/"
healthcheckTimeout = 300
restartPolicyType = "on_failure"
restartPolicyMaxRetries = 3
```

### Step 3: Downgrade Next.js (Fix Turbopack Issues)
Next.js 16.x enables Turbopack by default, which breaks workspace resolution.

**Files to modify:**
- `apps/web/package.json`: Change `"next": "16.2.4"` → `"next": "15.2.4"`
- `apps/web/package.json`: Change `"eslint-config-next": "16.2.4"` → `"eslint-config-next": "15.2.4"`

### Step 4: Commit & Deploy
```bash
git add -A
git commit -m "fix: use Nixpacks, downgrade Next.js 15 for Railway"
git push origin master
railway up --detach
```

### Step 5: Set Environment Variables in Railway Dashboard
1. Add PostgreSQL service if not added
2. Set variables:
   - `DATABASE_URL` → Reference PostgreSQL service variable
   - `NEXT_PUBLIC_APP_URL` = `https://sincere-optimism.up.railway.app`
   - `NEXT_PUBLIC_BASE_URL` = `https://sincere-optimism.up.railway.app`
   - `OPENAI_API_KEY` = your API key

## Why This Works
- **Nixpacks** auto-detects monorepo and runs correct build commands
- **Next.js 15** doesn't enable Turbopack by default
- **No Dockerfile** = no multi-stage build symlink issues
