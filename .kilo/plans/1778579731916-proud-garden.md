## Bugs Found in Current Implementation

### B1. SECURITY: `adminKey=bypass` allows public access to templates API
**File:** `app/api/site-admin/templates/route.ts:19`
```ts
if (bypass === "bypass") return true;
```
Anyone can append `?adminKey=bypass` to the URL and access all template operations without auth.
**Fix:** Remove the bypass entirely. Use only `x-user-id` header + `isAdmin()`.

### B2. Template upload fails — auth check never passes
**File:** `app/site-admin/page.tsx:155-159` + `app/api/site-admin/templates/route.ts:46-47`
- The frontend sends `formData.append("adminKey", "bypass")` in the POST body
- The API checks `formData.get("userId")` — but `userId` is never appended to formData
- The API's `checkAuth()` checks URL query params for `adminKey`, not form body fields
- `x-user-id` header is not sent with the POST fetch call
**Fix:** Send `x-user-id` header in the POST fetch call. Remove `adminKey` from formData. Remove bypass from checkAuth.

### B3. Template delete exposes `adminKey=bypass` in URL
**File:** `app/site-admin/page.tsx:177`
```ts
fetch(`/api/site-admin/templates?adminKey=bypass&templateId=${tid}`, ...)
```
The bypass key appears in server access logs, proxy logs, and browser URL history.
**Fix:** Use `x-user-id` header instead of URL query param. Remove bypass from checkAuth.

### B4. Refresh button passes stale `page` state
**File:** `app/site-admin/page.tsx:246`
```ts
onClick={() => { fetchTabData(activeTab, page); }}
```
The refresh button in the header captures `page` from the closure but the pages for stores/users/orders use different pagination. On Dashboard and Templates tabs, `page` should be 1. On paginated tabs, it should use the current page.
**Fix:** For non-paginated tabs, always use page 1. For paginated tabs, use the current page state.

### B5. Pagination component shows on Dashboard/Templates tabs
**File:** `app/site-admin/page.tsx:558-565`
The pagination UI renders whenever `totalPages > 1`. On Dashboard and Templates tabs, `totalPages` is never reset to 1 when switching tabs, so stale values could show pagination UI where it doesn't apply.
**Fix:** Reset `totalPages` to 1 when switching to tabs without pagination.

### B6. Missing error feedback on failed template upload
**File:** `app/site-admin/page.tsx:168-169`
```ts
else setMessage({ type: "error", text: data.error || "Upload failed" });
```
If the auth check fails (403), the user gets no actionable message about why.
**Fix:** Check response status and show specific messages for auth failures.
